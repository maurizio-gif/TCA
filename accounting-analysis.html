Cloud Accounting Software — API Analysis

The carve-out requires migrating TCA's accounting software by December. This analysis compares cloud accounting platforms for Italy on their public API catalogs, against two requirements — scoped to true general-ledger accounting (chart of accounts, double-entry, balances). Invoicing-only tools such as Fatture in Cloud do not qualify as the accounting backend.

●  Hard Deadline: December 2026
Requirement 01 · Import (POST)

Push revenue data from the club's management system into the ledger, broken down by GL account and payment type/method (ideally also by revenue center).

Requirement 02 · Extract (GET)

Pull consolidated data (account balances, trial balance, aggregated income/expenses) to feed dynamic external dashboards — Power BI, Looker Studio, custom apps.

02 · The Finalists

Finalist #1 · First Choice
TeamSystem Contabilità in Cloud (ex Reviso)

The only Italian-native cloud product that satisfies both requirements through a publicly documented REST API, at SME-friendly cost.

  • POST: journal entries and invoices via vouchers onto a real, customizable chart of accounts — revenue posted per account with the right counterpart (cash, bank, POS) covers the payment-type breakdown.
  • GET: the accounts resource exposes balance per account plus entries by fiscal year/period — a trial balance via API, ready for dashboards.
  • Auth: dual token (AppSecret + AgreementGrant); free demo environment.
  • Condition: obtain written confirmation of the product roadmap from TeamSystem (the product is the rebranded Reviso) before signing.
Finalist #2 · Most Powerful
Odoo Enterprise + Italian Localization

The most powerful and future-proof option: full GL API, native SDI e-invoicing, built-in dashboards — at the price of a partner-led implementation.

  • Compliance: mature l10n_it_edi — FatturaPA through Odoo's accredited SDI proxy, withholding, Ri.Ba., DDT, VAT export; receipts via PoS + RT printers.
  • POST: account.move (any journal entry, lines per GL account) and account.payment (journal = payment method/account).
  • GET: read_group on account.move.line for balances, trial balance and P&L per period.
  • Caveat: External API only on Custom plans (or Odoo.sh / self-hosted); weigh the implementation project against the December deadline.
Fallbacks
TeamSystem Enterprise · Passepartout

TSE in Cloud is a real candidate on paper (public developer portal with accounting movement services) but it is a full mid-market ERP — oversized for a club. Passepartout Passcom/Mexal is true accounting with a documented WebAPI, but journal-entry POST and balance GET would go through a partner-built PassBuilder/Sprix customization: feasible, with lock-in and custom development to budget.

Where Fatture in Cloud Still Fits
Complementary Layer Only

Best-documented API on the Italian market (OpenAPI spec, 8 SDKs, webhooks, API included in every paid plan) with native payment_account, revenue centers and SDI sending — but no chart of accounts, no double-entry, no balance endpoints. If the chosen GL system lacks a good SDI front-end, it could serve as the invoicing/receipts layer feeding the ledger; otherwise it drops out of the architecture.

03 · Next Steps

  1. Confirm the accounting perimeter with the accountant: full double-entry in-house vs. cash-basis management with the GL at the firm — this validates the scoping assumption of this analysis.
  2. Open test accounts: Contabilità in Cloud / Reviso demo + an Odoo trial with the Italian localization.
  3. Two-week proof of concept: POST one real day of revenue (courts, bar, membership fees) with accounts and payment methods, then GET balances into a prototype Power BI / Looker Studio dashboard.
  4. Obtain TeamSystem's roadmap commitment for Contabilità in Cloud before contract signature.
